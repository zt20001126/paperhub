# 用户登录注册功能技术文档

## 1. 文档说明

本文档基于 `docs/用户登录注册功能.md` 编写，用于指导 PaperHub 登录注册功能的技术优化落地。

当前系统已经具备基础登录注册能力，但验证码相关数据仍存在内存中。优化后，图形验证码、邮箱验证码、发送冷却、登录失败次数等短生命周期数据统一放入 Redis。

## 2. 当前实现概况

后端模块：

```text
paperhub-server/
  paperhub-business/
  paperhub-common/
  paperhub-entity/
```

认证相关代码：

| 文件 | 当前职责 |
| --- | --- |
| `paperhub-business/src/main/java/org/paperhub/auth/controller/AuthController.java` | 认证接口入口 |
| `paperhub-business/src/main/java/org/paperhub/auth/service/impl/AuthServiceImpl.java` | 注册、登录、发送验证码等业务逻辑 |
| `paperhub-business/src/main/java/org/paperhub/auth/service/CaptchaService.java` | 生成和校验图形验证码 |
| `paperhub-business/src/main/java/org/paperhub/auth/service/EmailCodeService.java` | 发送和校验邮箱验证码 |
| `paperhub-entity/src/main/java/org/paperhub/auth/dto/RegisterRequest.java` | 注册请求 DTO |
| `paperhub-entity/src/main/java/org/paperhub/auth/dto/LoginRequest.java` | 登录请求 DTO |
| `paperhub-entity/src/main/java/org/paperhub/auth/dto/SendCodeRequest.java` | 发送邮箱验证码请求 DTO |
| `paperhub-entity/src/main/java/org/paperhub/auth/vo/CaptchaVO.java` | 图形验证码返回 VO |
| `paperhub-entity/src/main/java/org/paperhub/auth/vo/LoginUserVO.java` | 登录成功返回 VO |

当前主要问题：

1. `CaptchaService` 使用 `ConcurrentHashMap` 保存图形验证码，不支持多实例部署。
2. `EmailCodeService` 使用 `ConcurrentHashMap` 保存邮箱验证码，服务重启后验证码丢失。
3. 邮箱验证码缺少 Redis 级别过期和发送冷却控制。
4. 图形验证码缺少错误次数限制。
5. 登录接口 DTO 当前只有邮箱和密码，需要补充 `captchaId`、`captchaCode`。
6. 登录流程当前未校验图形验证码，需要按 PRD 补齐。
7. 登录失败次数目前未做限制，需要增加 Redis 计数。

## 3. 总体技术方案

### 3.1 方案概述

使用 Redis 承载登录注册过程中的临时状态：

- 图形验证码：`captchaId -> code`
- 邮箱验证码：`email -> code`
- 邮箱验证码发送冷却：`email -> cooldown`
- 图形验证码错误次数：`captchaId -> failCount`
- 邮箱验证码错误次数：`email -> failCount`
- 登录失败次数：`account -> failCount`

服务职责保持清晰：

| 服务 | 职责 |
| --- | --- |
| `CaptchaService` | 生成图形验证码、写入 Redis、校验图形验证码 |
| `EmailCodeService` | 生成邮箱验证码、发送邮件、写入 Redis、校验邮箱验证码 |
| `AuthServiceImpl` | 编排注册、登录、发送验证码主流程 |
| `RedisKeyConstants` | 统一维护 Redis Key 前缀和生成方法 |
| `AuthProperties` | 统一维护验证码、密码、登录限制配置 |

### 3.2 技术选型

| 技术 | 用途 |
| --- | --- |
| Spring Boot 2.7.18 | 后端服务框架 |
| Spring Validation | 请求参数校验 |
| Spring Mail | 邮箱验证码发送 |
| Spring Security Crypto | BCrypt 密码加密 |
| MyBatis-Plus | 用户数据读写 |
| Redis | 验证码、冷却和失败次数存储 |
| `StringRedisTemplate` | Redis 字符串读写 |

建议新增配置项：

```yaml
paperhub:
  auth:
    captcha:
      expire-seconds: 300

    email-code:
      expire-seconds: 300
      cooldown-seconds: 60
      max-fail-count: 5
```

## 5. Redis Key 设计

### 5.1 Key 汇总

| 业务 | Redis Key | TTL |
| --- | --- | --- |
| 图形验证码 | `auth:captcha:{captchaId}` | 300 秒 |
| 图形验证码错误次数 | `auth:captcha:fail:{captchaId}` | 跟随图形验证码有效期 |
| 注册邮箱验证码 | `auth:email-code:register:{email}` | 300 秒 |
| 注册邮箱验证码错误次数 | `auth:email-code:fail:register:{email}` | 跟随邮箱验证码有效期 |
| 注册邮箱验证码发送冷却 | `auth:email-code:cooldown:register:{email}` | 60 秒 |
| 登录失败次数 | `auth:login:fail:{account}` | 900 秒 |

### 5.2 Key 常量类

建议新增：

```text
paperhub-business/src/main/java/org/paperhub/auth/constant/AuthRedisKeys.java
```

示例：

```java
public final class AuthRedisKeys {
    private AuthRedisKeys() {
    }

    public static String captcha(String captchaId) {
        return "auth:captcha:" + captchaId;
    }

    public static String captchaFail(String captchaId) {
        return "auth:captcha:fail:" + captchaId;
    }

    public static String registerEmailCode(String email) {
        return "auth:email-code:register:" + email;
    }

    public static String registerEmailCodeFail(String email) {
        return "auth:email-code:fail:register:" + email;
    }

    public static String registerEmailCodeCooldown(String email) {
        return "auth:email-code:cooldown:register:" + email;
    }

    public static String loginFail(String account) {
        return "auth:login:fail:" + account;
    }
}
```

## 6. 接口设计

接口路径保持现有设计：

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/auth/captcha` | `GET` | 获取图形验证码 |
| `/api/auth/send-code` | `POST` | 发送注册邮箱验证码 |
| `/api/auth/register` | `POST` | 注册 |
| `/api/auth/login` | `POST` | 登录 |

### 6.1 获取图形验证码

请求：

```text
GET /api/auth/captcha
```

返回：

```json
{
  "success": true,
  "message": "OK",
  "data": {
    "captchaId": "6db174b0d2f54bd9a5e2c2a9e3f07d43",
    "imageBase64": "data:image/png;base64,...",
    "expiresInSeconds": 300
  }
}
```

处理逻辑：

1. 生成 4 位图形验证码字符。
2. 生成不可预测的 `captchaId`。
3. 将验证码答案转小写后写入 Redis。
4. 设置 TTL。
5. 生成图片 Base64 返回前端。

### 6.2 发送注册邮箱验证码

请求：

```text
POST /api/auth/send-code
```

请求体：

```json
{
  "email": "user@example.com",
  "captchaId": "6db174b0d2f54bd9a5e2c2a9e3f07d43",
  "captchaCode": "A7K9"
}
```

处理逻辑：

1. 参数校验。
2. 校验邮箱是否已注册。
3. 校验发送冷却 Key 是否存在。
4. 校验图形验证码。
5. 生成 6 位邮箱验证码。
6. 发送邮件。
7. 邮件发送成功后写入邮箱验证码 Key。
8. 写入发送冷却 Key。

注意：

- 邮件发送失败时不写入邮箱验证码。
- 图形验证码建议在校验成功后删除，避免重复使用。
- 如果希望用户注册提交时不再输入图形验证码，则注册接口不需要再次校验图形验证码。
- 如果保留注册提交时再次校验图形验证码，则发送邮箱验证码时不要删除图形验证码，但会降低一次性验证码的安全性。推荐采用“发送邮箱验证码校验图形验证码，注册提交只校验邮箱验证码”的方案。

### 6.3 注册

请求：

```text
POST /api/auth/register
```

请求体：

```json
{
  "email": "user@example.com",
  "emailCode": "123456",
  "password": "abc123456",
  "confirmPassword": "abc123456"
}
```

推荐改造：

- `RegisterRequest` 保留 `email`、`emailCode`、`password`、`confirmPassword`。
- 如果继续保留 `captchaId`、`captchaCode`，则注册页需要重新获取一张图形验证码用于最终注册提交。
- 为了减少用户输入和避免同一图形验证码复用，推荐注册接口不再接收图形验证码，图形验证码只用于发送邮箱验证码前置校验。

处理逻辑：

1. 参数校验。
2. 校验邮箱是否已注册。
3. 校验密码和确认密码是否一致。
4. 校验密码复杂度。
5. 校验邮箱验证码。
6. 创建用户。
7. 使用 BCrypt 加密密码。
8. 删除邮箱验证码和邮箱验证码错误次数 Key。

### 6.4 登录

请求：

```text
POST /api/auth/login
```

请求体：

```json
{
  "email": "user@example.com",
  "password": "abc123456",
  "captchaId": "6db174b0d2f54bd9a5e2c2a9e3f07d43",
  "captchaCode": "A7K9"
}
```

DTO 改造：

```text
paperhub-entity/src/main/java/org/paperhub/auth/dto/LoginRequest.java
```

需要新增字段：

```java
@NotBlank(message = "图形验证码ID不能为空")
private String captchaId;

@NotBlank(message = "图形验证码不能为空")
private String captchaCode;
```

处理逻辑：

1. 参数校验。
2. 校验账号是否处于登录锁定期。
3. 校验图形验证码。
4. 查询用户。
5. 校验用户状态。
6. 校验密码。
7. 登录成功后清除登录失败次数。
8. 返回登录用户信息和 token。

失败处理：

- 图形验证码错误：增加图形验证码错误次数，达到上限删除验证码。
- 账号不存在或密码错误：返回统一提示“账号或密码错误”。
- 密码错误：增加登录失败次数。
- 登录失败次数达到上限：锁定账号 15 分钟。

## 7. 服务实现设计

### 7.1 CaptchaService

改造目标：

- 移除 `ConcurrentHashMap<String, CaptchaRecord>`。
- 注入 `StringRedisTemplate`。
- 验证码答案写入 Redis。
- 校验时从 Redis 读取。
- 支持错误次数限制。

核心方法：

```java
CaptchaVO createCaptcha();

void verify(String captchaId, String captchaCode);
```

伪代码：

```java
public CaptchaVO createCaptcha() {
    String code = randomCode();
    String captchaId = randomId();
    redis.opsForValue().set(
        AuthRedisKeys.captcha(captchaId),
        code.toLowerCase(),
        captchaExpireSeconds,
        TimeUnit.SECONDS
    );
    return buildCaptchaVO(captchaId, code);
}

public void verify(String captchaId, String captchaCode) {
    String key = AuthRedisKeys.captcha(captchaId);
    String storedCode = redis.opsForValue().get(key);
    if (storedCode == null) {
        throw new BizException("图形验证码错误或已过期");
    }
    if (!storedCode.equals(captchaCode.trim().toLowerCase())) {
        increaseCaptchaFailCount(captchaId);
        throw new BizException("图形验证码错误或已过期");
    }
    redis.delete(key);
    redis.delete(AuthRedisKeys.captchaFail(captchaId));
}
```

错误次数处理：

```java
private void increaseCaptchaFailCount(String captchaId) {
    String failKey = AuthRedisKeys.captchaFail(captchaId);
    Long count = redis.opsForValue().increment(failKey);
    if (count != null && count == 1L) {
        redis.expire(failKey, captchaExpireSeconds, TimeUnit.SECONDS);
    }
    if (count != null && count >= captchaMaxFailCount) {
        redis.delete(AuthRedisKeys.captcha(captchaId));
        redis.delete(failKey);
    }
}
```

### 7.2 EmailCodeService

改造目标：

- 移除 `ConcurrentHashMap<String, CodeRecord>`。
- 使用 Redis 保存邮箱验证码。
- 增加发送冷却。
- 增加错误次数限制。
- 邮件发送成功后再写入 Redis。

核心方法：

```java
void sendRegisterCode(String email);

void verifyRegisterCode(String email, String code);
```

发送伪代码：

```java
public void sendRegisterCode(String email) {
    String cooldownKey = AuthRedisKeys.registerEmailCodeCooldown(email);
    if (Boolean.TRUE.equals(redis.hasKey(cooldownKey))) {
        throw new BizException("发送过于频繁，请稍后再试");
    }

    String code = randomSixDigitCode();
    sendMail(email, code);

    redis.opsForValue().set(
        AuthRedisKeys.registerEmailCode(email),
        code,
        emailCodeExpireSeconds,
        TimeUnit.SECONDS
    );
    redis.opsForValue().set(
        cooldownKey,
        "1",
        emailCodeCooldownSeconds,
        TimeUnit.SECONDS
    );
    redis.delete(AuthRedisKeys.registerEmailCodeFail(email));
}
```

校验伪代码：

```java
public void verifyRegisterCode(String email, String code) {
    String key = AuthRedisKeys.registerEmailCode(email);
    String storedCode = redis.opsForValue().get(key);
    if (storedCode == null) {
        throw new BizException("邮箱验证码错误或已过期");
    }
    if (!storedCode.equals(code)) {
        increaseEmailCodeFailCount(email);
        throw new BizException("邮箱验证码错误或已过期");
    }
    redis.delete(key);
    redis.delete(AuthRedisKeys.registerEmailCodeFail(email));
}
```

### 7.3 AuthServiceImpl

发送邮箱验证码：

```text
sendRegisterCode
  -> 校验邮箱格式
  -> 查询邮箱是否已注册
  -> 校验发送冷却
  -> 校验图形验证码
  -> 发送邮箱验证码
```

注册：

```text
register
  -> 校验邮箱是否已注册
  -> 校验密码规则
  -> 校验确认密码
  -> 校验邮箱验证码
  -> BCrypt 加密密码
  -> 保存用户
```

登录：

```text
login
  -> 校验登录失败锁定
  -> 校验图形验证码
  -> 查询用户
  -> 校验用户状态
  -> 校验密码
  -> 失败时记录登录失败次数
  -> 成功时清除登录失败次数
  -> 生成 token 并返回
```

### 7.4 LoginFailService

建议新增独立服务：

```text
paperhub-business/src/main/java/org/paperhub/auth/service/LoginFailService.java
```

职责：

- 判断账号是否被锁定。
- 登录失败时增加失败次数。
- 登录成功时清除失败次数。

方法建议：

```java
void checkLocked(String account);

void recordFail(String account);

void clearFail(String account);
```

实现规则：

- 第一次失败时设置 TTL 为 `login.lock-seconds`。
- 失败次数达到 `login.max-fail-count` 后，锁定到 TTL 结束。
- 登录成功后删除失败次数 Key。

## 9. 异常处理

统一使用 `BizException` 抛出业务异常，由 `GlobalExceptionHandler` 转换为统一 `Result`。

推荐错误提示：

| 场景 | 提示 |
| --- | --- |
| 图形验证码缺失 | 图形验证码错误或已过期 |
| 图形验证码错误 | 图形验证码错误或已过期 |
| 邮箱验证码缺失 | 邮箱验证码错误或已过期 |
| 邮箱验证码错误 | 邮箱验证码错误或已过期 |
| 邮箱验证码发送频繁 | 发送过于频繁，请稍后再试 |
| 邮箱已注册 | 该邮箱已注册 |
| 密码不一致 | 两次输入的密码不一致 |
| 密码强度不足 | 密码至少 8 位，并包含字母和数字 |
| 账号不存在 | 账号或密码错误 |
| 密码错误 | 账号或密码错误 |
| 登录失败次数过多 | 登录失败次数过多，请稍后再试 |
| Redis 异常 | 系统繁忙，请稍后再试 |
| 邮件发送异常 | 邮件发送失败，请稍后再试 |

安全要求：

- 登录时不区分“账号不存在”和“密码错误”。
- 日志不打印明文密码、邮箱验证码、图形验证码答案。
- Redis 异常不要将底层连接信息直接返回前端。

## 10. 登录态说明

当前 `AuthServiceImpl` 使用静态 `ConcurrentHashMap` 保存 token 和用户 ID：

```java
private static final ConcurrentHashMap<String, Long> TOKEN_USER_MAP = new ConcurrentHashMap<>();
```

本次 PRD 重点是登录注册验证码优化，token 存储可以暂不改造。

后续建议：

- 将 token 也迁移到 Redis。
- token 增加过期时间。
- 或使用 JWT 替代内存 token。

## 11. 数据一致性要求

### 11.1 注册一致性

注册成功后必须删除：

```text
auth:email-code:register:{email}
auth:email-code:fail:register:{email}
```

注册失败时：

- 邮箱验证码错误：增加错误次数。
- 密码错误或邮箱已注册：不删除邮箱验证码。
- 数据库写入失败：不应删除邮箱验证码，用户可稍后重试。

### 11.2 发送验证码一致性

邮件发送成功后才写入：

```text
auth:email-code:register:{email}
auth:email-code:cooldown:register:{email}
```

邮件发送失败时：

- 不写入邮箱验证码。
- 不写入冷却 Key，允许用户稍后重试。

### 11.3 图形验证码一致性

图形验证码校验成功后必须删除：

```text
auth:captcha:{captchaId}
auth:captcha:fail:{captchaId}
```

图形验证码错误次数达到上限后必须删除：

```text
auth:captcha:{captchaId}
auth:captcha:fail:{captchaId}
```

## 12. 并发和幂等

### 12.1 邮箱验证码发送并发

问题：

- 用户连续点击发送按钮，可能产生多个验证码和多封邮件。

处理：

- 先检查冷却 Key。
- 发送成功后写入冷却 Key。
- 如果需要更严格控制，可使用 Redis `SET key value NX EX 60` 先占位，发送失败时删除占位 Key。

### 12.2 注册并发

问题：

- 同一邮箱同时提交注册，可能出现重复创建。

处理：

- 数据库 `email` 字段必须有唯一索引。
- 业务层注册前查询邮箱是否存在。
- 捕获数据库唯一索引冲突并返回“该邮箱已注册”。

### 12.3 验证码校验并发

问题：

- 同一个验证码可能被并发提交多次。

处理：

- 校验成功后立即删除 Redis Key。
- 对严格一次性要求较高时，可用 Lua 脚本完成“读取、比较、删除”的原子操作。
- 当前阶段可以接受先读后删，但需要认识到极端并发下存在重复通过的可能。

## 17. 风险和注意事项

1. Redis 未启动会导致验证码功能不可用，需要在开发和部署文档中明确 Redis 依赖。
2. 如果注册接口继续校验图形验证码，需要避免发送邮箱验证码和注册提交复用同一个图形验证码。
3. 邮件服务可能较慢，必要时可改为异步发送。
4. 极端并发下验证码校验可能出现重复通过，后续可通过 Lua 脚本增强原子性。
5. 现有代码中部分中文提示可能存在编码显示异常，实施时建议统一源码编码为 UTF-8。
